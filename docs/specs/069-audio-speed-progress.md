# 会話音声の自動調整の高速化と進捗


## 高速化

会話モードは、入力全体を1回デコードしながら解析と動的な音声調整を同時に行う。従来捨てていた最初のloudnormパスの調整済み音声を直接FLACに保存し、そのパスの入力・出力測定値を利用する。ピーク余裕内の一定ゲインでは−16 LUFSとの差が0.3 LUを超えて残る場合のみ、測定済みの値を使う追加パスで音量を仕上げる。その後、必要ならピーク余裕内の一定ゲインを追加する。音楽など向けの「音量をそろえる」モードは測定値を使う2パス正規化を維持し、どちらのモードも完成FLACの再解析を省く。FLACは可逆の高速圧縮設定を使う。会話の高速経路と追加パスが必要な素材を分けて性能を測定する。

会話の80Hzハイパスと3:1コンプレッション、−16 LUFS・−1.5 dBTPの目標、LRA設定、48kHzステレオ、音声開始位置を維持する。実際の出力ファイルを独立に再測定して音量・ピーク・時間を検証する。既存の有効な処理済みキャッシュを再利用し、同じ元素材から分割・複製した複数クリップは1回だけ準備する。適用は対象全クリップへの1回の履歴にまとめる。

## 進捗

- FFmpegの `-progress` で処理済み秒数を取得し、登録済み素材の全長と段階別の配分から進捗を計算する。解析、音声処理、必要な補正、保存、キャッシュ再利用を区別する。
- 全体の進捗％とバー、処理中の素材番号、経過時間、算出可能な場合の残り目安を表示する。複数素材では処理対象の全長で重み付けする。未完了は最大99%、適用完了後のみ100%。
- 進捗は実際の処理位置に基づき、時間の経過だけで増やさない。開始直後など見積もれない間は残り目安を算出中と表示する。処理位置の更新が止まった場合も経過時間を更新する。
- 音声プロパティとタイムラインの共通表示で確認でき、右クリックから始めても見失わない。キャンセルは既存の両方のボタンから使える。
- 各要求のIDで進捗を識別し、古い要求から届いたイベントを無視する。プロジェクト変更・Undo・ロック変更・中止で部分適用しない。共有処理は利用者ごとに購読を解除し、他の利用者を巻き添えにしない。

## 検証

旧処理と新処理を同じ生成素材で比較し、初回の処理時間とキャッシュ再利用時間を記録する。音量とピークを出力ファイルから独立測定し、ステレオ・時間・非破壊を確認する。進捗の解析、単調性、完了・取消・購読解除、複数クリップの素材重複除去、遅延イベントをテストする。Windowsアプリで実際の％表示・中止・再適用・保存と、既存の正逆再生・書き出しを検証する。

参照: [FFmpeg loudnorm](https://ffmpeg.org/ffmpeg-filters.html#loudnorm)、[FFmpeg progress](https://ffmpeg.org/ffmpeg.html#Advanced-options)。
