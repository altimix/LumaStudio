# CPU書き出しのスレッド自動選択

Issue: https://github.com/altimix/LumaStudio/issues/103

CPUのH.264書き出しでは、固定の4スレッド上限を外し、FFmpeg / libx264の`-threads 0`で利用可能なCPUに応じたスレッド数を選ぶ。書き出し全体の複合フィルターも固定の2スレッド上限を外し、`-filter_complex_threads 0`でFFmpegに選ばせる。ドラフト・標準・高画質のプリセットとCRF、フィルターの内容と順序、音声、FPS、GPUエンコーダーの引数は変更しない。GPU失敗時にCPUで最初から再試行する経路にも同じ設定を適用する。

出力先への一時ファイル作成、完成後の置換、中止時の削除は従来どおりとする。映像のビット列はスレッド数によって変わり得るため、フレーム数・長さ・映像と音声の内容を比較する。速度はCPU、素材、解像度、エフェクト、保存先によって変わり、以下の倍率を保証しない。

## 同条件での測定

Apple M2 Pro（10コア）、同梱FFmpeg 6.1.1、付属デモ映像8秒、30fps、CPUの標準品質（`medium`、CRF 21）。同じFFmpegフィルターグラフから生成したMP4を、エンコーダー4スレッドと自動設定で交互に各2回測定した。ここでは複合フィルターのスレッド数を2に固定し、エンコーダーだけを比較した。

| 出力 | 4スレッド | 自動選択 |
| --- | ---: | ---: |
| 1920×1080 | 4.06秒 / 4.09秒 | 2.02秒 / 2.02秒 |
| 3840×2160 | 16.31秒 / 16.43秒 | 7.92秒 / 7.76秒 |

4Kの両出力は8.000秒・240フレーム。AAC音声データはバイト単位で一致した。4K映像の相互PSNRは平均54.02 dBで、CRFとプリセットは同一。ドラフト品質の1080pでは4スレッド0.49秒、自動選択0.44秒だった。

同じデモ映像に中央50%のモザイクを付けた2秒・1280×720・30fpsの書き出しでは、エンコーダーを自動設定に固定し、複合フィルターだけを交互に各2回比較した。

| 複合フィルター | 1回目 | 2回目 |
| --- | ---: | ---: |
| 2スレッド | 19.44秒 | 19.38秒 |
| 自動選択 | 7.29秒 | 7.32秒 |

この4本のMP4はSHA256まで一致した。モザイクの画素、フレーム、音声はスレッド数によって変化していない。

`npm test`と両OSのパッケージ版操作検証で、編集内容、書き出し、キャンセル、既存ファイルの保護、GPUからCPUへの再試行を確認する。
