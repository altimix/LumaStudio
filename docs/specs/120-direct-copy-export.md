# 無編集MP4の再圧縮省略（Issue #120）

## 適用条件

「自動」、標準品質、シーケンスと同じ出力寸法・FPSを選んだ場合だけ、先に再圧縮なしの経路を判定する。動画は1本で、素材の先頭から全尺を使い、速度・位置・大きさ・回転・色・透明度・クロップ・マスク・モザイク・ぼかし・フェード・キーフレームを変更していないこと。通常の素材追加で自動作成されるリンク済みの映像・音声ペア、または音声未分離の動画クリップ1本を対象とする。音声の消音・音量変更・フェード・自動調整がなく、ほかのクリップやトランジションがないこと。現段階では1時間以内のMP4に限る。対象外のプロジェクトは従来の映像・音声処理へ戻る。

素材ファイルからメタデータと映像パケット時刻を確認する。MP4内のストリームはH.264 8-bit yuv420p映像とAAC 48 kHz stereo音声の2本だけとし、章情報、回転、非正方形ピクセルを除外する。映像の寸法、FPS、フレーム数、開始時刻、全パケットのPTSと長さ、映像・音声・コンテナの終了時刻がシーケンスと一致することを求める。平均FPSだけが合う可変FPS素材は通さない。素材の変更検証も省略しない。

適合した場合は元MP4の全バイトを保存先フォルダの一時ファイルへ複製し、素材を再検証した後に完成ファイルへ置き換える。これにより映像・音声は元ファイルとバイト単位で一致する。中止や書き込みエラーでは一時ファイルを消し、既存の完成MP4を残す。元ファイルを保存先に指定することも拒否する。GPU/CPUの手動指定と高画質・ドラフト設定では従来方式を使う。再圧縮時の音声設定は48 kHz / 192 kbpsだが、再圧縮を省く場合は元のAAC音声を保持する。

## 実測

Apple M2 Proで合成したH.264/AAC素材を960×540・24 FPS・標準品質で書き出し、通常の読み込みで作るリンク済み映像・音声ペアと同じ構成を使って、各経路を1回ウォームアップした後、交互に5回測った。操作開始から`exportProject`完了までを計測し、素材の取り込みと保存ダイアログでの操作は含まない。

| 素材 | CPU再圧縮の5回（秒） | 再圧縮なしの5回（秒） | 中央値 |
| --- | --- | --- | --- |
| 2秒・48フレーム | 0.182 / 0.179 / 0.187 / 0.189 / 0.183 | 0.017 / 0.015 / 0.018 / 0.017 / 0.017 | 0.183 → 0.017秒 |
| 8秒・192フレーム | 0.474 / 0.471 / 0.470 / 0.502 / 0.535 | 0.018 / 0.017 / 0.018 / 0.016 / 0.019 | 0.474 → 0.018秒 |

`node scripts/benchmark-export-direct-copy.cjs`で同じ比較を再実行できる。再圧縮なしの出力は元ファイルと全バイト一致し、両経路のフレーム数・長さ・音声サンプルレートは一致した。この短い生成素材とPCだけの結果であり、長尺素材や遅いディスクで同じ短縮幅を保証しない。

## 検証

実メディアで音声を含む全バイト一致、可変FPSと回転の除外、リンク済み音声の音量変更時の通常経路、保存済み出力の保護、中止後の一時ファイル削除を確認する。Windows/macOSの配布版では通常のUI操作で素材を追加し、2クリップのリンクと再圧縮省略を確認してから、MP4再取り込みと音声再生も確認する。
