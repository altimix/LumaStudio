# 再生ヘッドにタイムラインを追従


この文書は1.4.1の再生追従の基礎仕様。1.4.2以降の停止中の移動、再指定、マウス端スクロールは [013-complete-playhead-follow.md](013-complete-playhead-follow.md) を適用する。

## 動作

- 再生中、再生ヘッドが左右端から48px以内に近づくと横スクロールする。狭い表示では幅の12%を余白の上限にする。
- 順方向は表示幅の25%、逆方向は75%の位置へ送る。前方または後方の編集点を見渡せるようにし、スクロール可能な範囲で制限する。
- 再生速度に遅れないよう即時スクロールを使う。1/SpaceとJ/Lの全倍率で共通とし、音声時計・再生位置・編集データを変更しない。
- 先頭/末尾からの再生開始、方向変更、先頭/末尾で自動停止した最後のフレームも表示範囲に収める。
- 再生中のズームと表示幅変更にも対応する。表示幅はResizeObserverで監視し、毎フレーム監視を作り直さない。
- 追従は横方向だけを変更し、縦スクロールとトラック名の位置を保持する。

## 操作

- タイムラインの「再生ヘッドの自動追従」ボタンは起動時ON。再生中でも切り替えられ、OFF時は現在位置に関係なく自由にスクロールできる。
- ON/OFFは表示用の一時設定で、プロジェクトの保存内容やUndo履歴に含めない。同じアプリ内で別のプロジェクトを開いても設定を引き継ぐ。
- 「再生ヘッドを表示」は、再生中・停止中を問わず現在位置を中央に表示する。両端ではスクロール可能な位置へ制限する。再生・停止状態は変えない。
- Kで停止した後は表示範囲を動かさず、手動スクロールを維持する。再生を再開すると追従を再開する。
- ルーラーや再生ヘッドのドラッグでは停止し、ポインター位置を優先する。停止直後の追従によってドラッグ開始位置をずらさない。

## 検証

`scripts/verify-timeline-follow.cjs` はWindows実アプリで120秒・12トラックの検証プロジェクトを開き、ズーム200px/秒で実際にJ/Lを入力する。1/2/4/8/16倍速の両方向について、アニメーションフレームごとのDOM座標が表示内にあることと、表示範囲が再生方向へ動くことを確認する。

K/L再開、停止中の手動スクロール、OFF/ON、中央表示、縦スクロール保持、ズーム、ウィンドウ幅変更、端点での開始/停止、ルーラー操作、編集データとUndo履歴を確認する。結果は `timeline-follow-verification.json`、画面は `timeline-follow.png`。配布EXEでも実行し、既存の編集・音声・保存・YouTube検証を維持する。
