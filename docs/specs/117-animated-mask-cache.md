# 動くマスクの書き出し準備キャッシュ（Issue #117）

## 現状と目標

`electron/export.cjs` は動くマスクの各フレームを `maskFrame` でPGMへ描き、`writeFrameSequence` でFFV1の一時MKVを作る。同じ編集を再書き出ししても、一時MKVは消えるため毎回再生成する。

Apple M2 Proで同梱デモ8秒・960×540・24 FPS、動く矩形マスクを使ったCPU標準品質の書き出しは、3回の準備時間が0.329/0.359/0.336秒、完了までが0.931/0.957/0.925秒だった。初回インポートとUI操作は含まない。これは導入前の基準であり、別のPC・長さで同じ効果を保証しない。

候補実装では初回の準備0.347秒・全体0.940秒、続く3回の準備0.002/0.002/0.002秒・全体0.596/0.589/0.586秒だった。実際の8秒デモでの再書き出し短縮であり、初回を速くする効果はない。完成MP4のバイト数は各回373615バイトで一致した。

## 適用と無効化

- 初期対象は動くマスクのPGM→FFV1列だけ。静的マスクやテロップ、元素材の映像・音声、プロキシは扱わない。
- アプリと描画実装、FFmpeg実体、出力FPS、マスク寸法、素材の識別・寸法、区間、クリップとキーフレームの全設定をキャッシュキーへ含める。該当する項目が変われば再生成する。
- キャッシュを使う前も、通常の素材登録・オフライン・変更検証を通す。Rendererはキャッシュのパスを選べない。
- 中間ファイルと内容検証情報を完成後に登録する。完成ファイルは毎回固有名にして、Windowsでも破損した旧ファイルへの上書きを避ける。FFprobe検証とハッシュ計算も中止できるようにする。中止・エラー・破損・未完成ファイルは再利用せず、再生成に失敗しても破損情報を掃除する。以前の完成MP4と元素材を守る。
- 同じキーを別のアプリプロセスが同時に準備した場合も、管理ファイルの公開はプロセス間ロック内で直列化し、Windowsで既存ファイルへのrenameに依存しない。
- 古いキャッシュをOSやウイルス対策ソフトが一時的に保持していて掃除に失敗しても、完成済みマスクを現在の書き出しに使う。容量を維持できなかった場合は新しい管理情報を可能な範囲で取り消し、次の掃除で再試行する。
- 容量上限と古いデータの掃除を設け、プロセス間ロックと利用中のリースで現在参照中のファイルを守る。利用者の操作でキャッシュを消せるようにする。
- 1件128 MiB、全体512 MiBを上限とする。大きい中間ファイルはその書き出しだけに使って後片付けし、キャッシュ登録しない。
- 最後の利用から30日を超えた完成済みデータは、次の掃除時に削除する。別のアプリプロセスが使用中のデータは期限を超えても残す。
- 手動削除の結果は使用中の完成ファイルに加えて、別プロセスが準備中の一時ファイルも数える。まだ0バイトの準備中ファイルでも使用中と通知し、全削除したとは表示しない。

## 検証

同じプロジェクトの初回・再書き出しで、準備時間と完成までの総時間、容量を複数回測る。設定変更、FPS・寸法変更、素材変更、キャッシュ破損・削除、アプリ再起動・中止を含める。完成MP4の全フレーム、長さ、48 kHz PCM音声、保存・Undo/Redo、Windows/macOS配布版の再取り込みと音声再生を確認する。
