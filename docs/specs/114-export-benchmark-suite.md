# 書き出しの総時間と内容を比較する計測基盤（Issue #114）

## 対象

同梱デモのH.264/AAC素材から2秒・960×540・24 FPSのCPU書き出しを行う。無加工、同じ素材の連続/飛び越し24カット、モザイク、ガウスぼかし、両効果、回転を伴うぼかし、二段の映像を含む。出力には元の音声を含める。素材の読み込みと書き出しの処理は実際の `exportProject` を使う。

`node scripts/benchmark-export-suite.cjs test-results/export-suite 5` は各ケースを1回ウォームアップし、順序をずらしながら5回測る。`totalSeconds` は `exportProject` 呼び出しから一時MP4の完成・出力先への置換・後片付けまで、`ffmpegSeconds` は書き出し用FFmpeg子プロセスの起動から終了までである。`otherSeconds` はその差で、エンコーダー解決、素材の再検査、マスクなどの準備、FFmpeg引数の生成、完了処理を含む。素材の初回インポート、Renderer側のテロップ画像生成、保存ダイアログの操作は含まない。これらを含むUI総時間は別途配布アプリで測る。

各MP4の全映像フレームをRGBAの `framemd5` で、音声を48 kHz・ステレオ16-bit PCMで復号してハッシュを記録する。フレーム数、長さ、出力バイト数も残す。同一計測内で映像・音声・長さが反復ごとに異なれば失敗とする。結果とMP4は `test-results/` 以下に保存し、Gitには含めない。

## 比較と判定

基準と候補のJSONを `node scripts/benchmark-export-suite.cjs --compare 基準.json 候補.json` で比較する。OS、CPU、FFmpeg、素材のSHA-256、設定、ケースが違う場合は比較を拒否する。各ケースの中央値、最小・最大、中央値絶対偏差（MAD）、FFmpeg時間の中央値、総時間の増減率を報告する。増減率が負なら候補が速い。

映像・音声ハッシュ、フレーム数、長さが一致しないケースは「差あり」と表示する。ハッシュ差は画質低下の証明ではないが、速度の改善だけで品質合格とはしない。各高速化PRで差分の位置・最大値・原因を検証する。ウォームアップや反復回数、同時実行による熱・負荷の影響を記録し、異なるマシンや異なる設定の結果を直接比較しない。4K・長尺・GPU・UI起点の計測はこの短いCPUスイートに追加せず、各経路の実機検証で別に扱う。
