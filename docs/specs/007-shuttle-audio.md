# シャトル音声と再開処理


## 利用者の動作

- Jは映像と音声を逆方向、Lは順方向に再生する。同じ方向のキーで1、2、4、8、16倍。Kで即座に停止し、次のJ/Lは現在の再生ヘッドから1倍で再開する。
- 音声の出力も倍率に追従し、速度に応じて音の高さが変化する。クリップに設定した速度も乗算する。シャトル操作は保存済みの速度やMP4出力を変更しない。
- カット、in点、クリップの音量・フェード、トラックのミュート・ソロを両方向で反映し、映像クリップに含まれる音声もミックスする。映像の非表示は消音とは独立する。
- 初回読み込みやシークで音声が未準備の場合は「音声準備中」を表示する。再生ヘッドを最後に再生可能な位置で待機させ、欠落した区間を飛ばさない。失敗時は停止し、具体的なエラーを通知する。

## 音声処理

- 動画要素は映像表示専用として常に消音する。正逆共通のWeb Audio時計でシーケンスを進め、音声と映像が別々の時計で進行しないようにする。
- 次の動画フレームをシークする前にデコード済みフレームを保持する。逆再生中にreadyStateが下がっても黒画面に戻さず、最後に取得できた映像を表示する。
- Windowsメインプロセスで登録済み素材の元ファイルから、48 kHz・ステレオ・float32の8秒窓をFFmpegで正確にデコードする。登録URLと窓番号のみをIPCで受け取り、任意のファイルパスは受け取らない。プロキシの音声に依存しない。
- AAC等の圧縮音声は窓の最大1秒前からデコードし、先行区間を捨てる。各窓の最初のサンプルから、連続デコードと同じ信号・コンテナー時刻を保つ。
- FFmpegは同時2プロセス、待機を含め32件、1件30秒まで。同じ窓への同時要求はまとめる。終了時に処理を中止する。
- レンダラーのPCMキャッシュは正逆合計64 MiBのLRU。必要な窓のみ反転して再利用する。長尺素材の全体展開を避ける。再リンク後はURLのrevisionで別キャッシュになる。
- レンダラーからの音声読み込みも同時2件に制限し、重なった素材と高速再生でIPCの待機上限を超えないようにする。停止・シーク・方向/倍率変更では古い待機要求を取り消し、すでに実行中の最大2件はデータとして再利用する。
- 最大0.4秒先を0.1秒単位で予約し、クリップ境界・素材窓境界をまたぐ音声をサンプル区間へ変換する。逆方向ではサンプル配列を反転し、各窓の正しい末尾側から読む。
- 予約する音声は48 kHzステレオの短いミックス済みバッファにする。元の8秒窓を再生予約ノードに保持しない。OfflineAudioContextで最大4区間ずつ速度・フェード・音量を適用して加算し、各バッチの終了時に素材バッファの参照を解放する。トラック数・倍率に応じて予約済みPCMが膨らまないようにする。
- 停止・方向変更・倍率変更・シーク・編集で予約済み音声を同期的に停止し、世代番号を更新する。古い非同期読み込みの完了は新しい再生を開始できない。K/Lが同じ描画フレーム内でも両方のコマンドを処理する。再生要求ごとにAudioContextをresumeする。
- Webデモのみブラウザーのデコードを使い、32 MiB・120秒以下に制限する。製品の長尺対応はWindows版で行う。

## 回帰検証

- 単体テストで素材参照区間、逆方向の窓境界、速度・カット・無音区間、ミュート・ソロ・オフライン、PCM反転・キャッシュ上限、非同期中止と再開を確認する。
- 実FFmpegで日本語・空白パス、窓の開始位置、末尾のゼロ埋め、範囲拒否、キュー上限を検証する。
- Windowsアプリの実キー入力と出力グラフから取得したPCMで、K→L反復、J→K→L、音声時計のsuspend後の素早いK→L、全倍率、逆順の実信号、停止後の無音と古い音の復帰防止を確認する。
- 既存の編集、復元、ファイル保護、キーフレーム、ショートカットとMP4出力のパッケージ検証も実行する。

この仕様は005の「逆方向・高速再生は消音」を置き換える。
