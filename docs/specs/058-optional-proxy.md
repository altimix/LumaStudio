# 任意の軽量プレビュー用プロキシ（#58）
- メディアパネルで動画を選択し「軽量プロキシを作成」を実行すると、互換形式の動画でも1280×720内のH.264/AACへ変換してプレビューに使う。縦横比と元素材の編集座標・時間を保つ。小さい動画は元の縦横寸法を超えて拡大しない。以前の変換設定で作成した動画キャッシュとは保存名を分ける。
- 元素材のパス・サイズ・解像度・IDは変えない。MP4出力と音声処理は原本を参照する。プロキシはキャッシュへ保存しプロジェクトの持ち運び素材には含めない。
- 作成中は既存の素材処理ダイアログに工程を表示し、中止できる。中止や失敗では既存の選択状態と素材を保持し、一時ファイルを除去する。
- 「軽量プロキシを解除」で原本へ戻す。原本形式が再生非対応なら、互換性のための自動プロキシを維持する。設定変更は1回のUndo/Redo、保存後の再読込でも設定を保持する。
- 異なるプレビューURLで原本とプロキシを登録し、切替やUndo時に動画デコーダーを読み直す。メイン側で登録済み原本・変更検知・動画種類を検証する。
- scripts/verify-optional-proxy.cjs は4K/30fps素材を600クリップ・30分のタイムラインに配置して起動、再生、切替、Undo/Redo、再読込を確認する。実際のChromium動画シーク5回を原本/プロキシで計測し、test-results/optional-proxy-performance.json に環境と実測値を記録する。単一端末・合成素材での値であり、すべての素材の高速化は保証しない。

## 実測例
2026-09-18、macOS arm64 / Apple M2 Pro、開発版、合成4K/30fps素材3秒を600回配置した30分シーケンス。プロジェクトを開くまで約247ms、軽量ファイル作成と切替約424ms。素材プレビューで5地点へシークした中央値は原本68.1ms、プロキシ11.6msだった。これは合成素材のデコード比較で、30分連続した原本の全編再生試験ではない。保存・Undo/Redo・再読込・タイムライン末尾への移動と冒頭再生も成功した。
