# 動画の内容を伝えるサムネイル

Issue #13。動画固有の主役・見せ場が一目で伝わる、高品質なYouTube向けサムネイルを作る。

- 横シーケンスは1536×864（16:9）、縦シーケンスは864×1536（9:16）。出力サイズをAPIへ明示し、返却画像も検査する。違うサイズは切り抜かずエラーとし、以前の画像を維持する。
- 保存はJPEG、ファイル全体を厳密に2,000,000バイト未満にする。大きい画像は解像度を維持して圧縮率を段階的に調整する。すでに小さいJPEGは再圧縮しない。既存PNGをJPEGとして保存する場合も実際に変換する。
- `gpt-image-2.5-sunburst`のhigh品質を使う（Issue #85）。選択した参考画像や実素材がある場合はImage Edit APIを使い、いずれもない場合はImage Generation APIを使う。
- 参考画像は表示トラック上の動画・画像の開始位置、in点、速度を反映して抽出する。映像が存在する区間の20%・50%・80%地点を採用し、先頭や途中の空白を除外する。重なる映像区間の時間は二重に数えない。非表示・オフライン・不透明度0のクリップや、タイムラインにない素材を使わない。素材パスはメイン側で登録状態を検証する。
- 動画名、現在の字幕・タイトル・概要・検索語、表示中のテロップとユーザーの希望を画像指示にまとめる。長い字幕は動画全体から最大24箇所を採用する。編集前の古い投稿データや、常に不透明度0のテロップは参考にしない。キーフレームがあるテロップはその値を優先し、一部でも見えるものだけを使う。
- 主役を大胆に拡大し、短い日本語見出し、2〜3色の配色、明暗差、文字と主役の配置を指定する。横・縦それぞれの構図と安全余白を使う。内容にない成果・数値・人物や誇張を創作しない。
- 投稿文未生成・生成指示が空欄でも、タイムラインに素材があれば作成できる。希望する見出しや強調点は任意で編集できる。
- 生成前の画面に送信内容とAPI利用料を表示する。処理は中止可能で、失敗時は以前の画像・プロジェクトを保持する。生成済み画像と現在の向きが違うときは再生成を案内する。
- 一時画像は検証と圧縮の完了後に確定し、失敗時は削除する。公開・投稿は自動で行わない。

## 検証

`tests/youtube-thumbnail.test.cjs`で参考画像の時刻・表示条件、動画内容、横縦API引数、高品質、サイズ拒否、中止、PNG変換と2MB制限を検証する。`scripts/verify-thumbnails.cjs`はAPI応答だけをモックし、Mac/Windowsの実アプリで参考画像抽出・両方向の生成・JPG保存・失敗時の旧画像保持を検証する。AIが実際に生成する構図や日本語文字の品質は、モック試験で保証しない。

API設定は[OpenAI公式の画像生成ガイド](https://developers.openai.com/api/docs/guides/image-generation)のGPT Image 2.5のサイズ・品質・入力画像仕様に従う。[Sunburstのモデル情報](https://developers.openai.com/api/docs/models/gpt-image-2.5-sunburst)も確認した（2026-09-20）。

## 任意の参考画像（Issue #85）

PNG・JPEG・WebPを1枚選択し、プレビュー・差し替え・解除できる。選択は `youtube.thumbnailReferenceAssetId` とプロジェクトの通常の画像素材として保存し、Undo/Redo・再読込・素材再リンクを維持する。字幕を再生成しても参考画像の指定は保持する。タイムラインへ自動配置しない。「素材をまとめて保存」ではタイムライン未使用の参考画像も同梱し、フォルダ移動後も読み込める。初期プロジェクトの素材IDを変更するときは参考画像の指定も追従する。選択・解除は外部送信を行わない。

生成時はユーザー画像を最初の1枚、動画の参考場面をその後に最大3枚送る。プロンプトでは最初の画像の人物・商品の特徴を優先し、動画の参考画像と顔や特徴を混ぜないことを指定する。写真そのままの一致は保証せず、作成後に見た目を確認するよう案内する。画像なしでも従来どおり作成でき、参考画像だけでも生成できる。

メイン側のファイル選択で1枚だけ受け付け、20MiB以下・4000万画素以下・各辺32768px以下の実際のPNG/JPEG/WebP画像であることを検証する。生成時にも登録済みの素材・ファイルの変更有無・画像形式を検証する。送信用に長辺1536px以内のJPEGへ変換し、ファイルのメタデータを除いて4MiB以下とする。元画像には書き込まない。

欠落・オフラインの参考画像は黙って省略せず、再リンク・選び直し・解除を案内する。旧プロジェクトは選択なしとして扱う。使用中の参考素材をプロジェクトから削除した場合は指定も解除し、Undoで戻せる。API応答をモックしたテストと実際のAI出力品質の確認は区別する。

外付けドライブの再接続などで元の参考画像が戻った場合、同じファイルを選び直すと、既存の素材IDを保持してオフライン情報を読み込み済みの情報へ置き換える。素材を重複登録せず、プレビューと生成を再開できる。

まとめ保存・初期プロジェクト・再リンク後は素材IDとファイル識別子（revision）が異なる場合があるため、選び直しでは両方を照合する。現在選択中の参考画像を優先し、素材ID・名前を保持する。素材が2000個ある場合も、既存画像の復帰は新規追加として拒否しない。

この照合と読み込み済み素材の登録はメイン側で一緒に行う。アプリを再起動して画像が欠落した状態で開いた場合も、画像を戻して選び直せば、プロジェクトを保存して開き直すことなく生成できる。Rendererは登録済みの戻り値のIDを書き換えない。
