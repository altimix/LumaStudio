# モザイク付き動画の書き出し高速化

Issue: https://github.com/altimix/LumaStudio/issues/110

v1.10.2では、モザイクをかけた映像の全画素に対して、複数の式による範囲判定と色参照を実行する。小さい指定範囲でもフレーム全体の計算時間がかかる。対象範囲だけを計算して元映像の同じ位置へ置き換え、書き出し全体の時間を短縮する。

この段階の高速経路は、実際にデコードした寸法と出力のアスペクト比が一致する、回転メタデータのない不透明なH.264動画に限定する。クロマキーや位置・サイズの動く映像には適用しない。モザイク範囲が画面の25%を超える場合は既存処理を使う。適用条件が不明な素材、透過画像、広いモザイクは従来の式を使う。出力時の画質設定、音声処理、シーケンス時間と素材時間、GPU/CPU方式は変更しない。

範囲内の処理は、既存のブロック原点、素材幅に対する粒サイズ、中央画素の採取、端の不完全な粒での参照位置の制限を保つ。RGBAのサンプル位置を一致させる。FFmpegの`geq`が範囲の右下隅の参照画素を変えないよう、利用可能な場合は右と下へ1画素広く切り出し、計算後に元の矩形へ戻す。元の映像とモザイク矩形を合成するときは、対象映像が不透明であるという適用条件を使う。

モザイク内部は従来の書き出しと圧縮前画素が一致する。旧処理の`geq`は指定範囲外でも画面最右端を再サンプリングしており、旧版との比較では最大8/255までの微差がその最右端に現れる場合がある。新方式の範囲外を過度に変化させないことを画素テストで検証する。プレビューと写真保存の方式は変更しない。

速度比較は同じ素材・設定で複数回測り、フィルター単体とMP4完成までの両方を記録する。モザイクなし・複数カットの速度退行も見る。固定の短縮倍率は保証しない。中止・失敗時の一時ファイル削除と既存出力の保護、Windowsポータブル版の音声再生を維持する。

Mac M2 Proの開発環境で、付属H.264デモを2秒・1280×720・30fps・CPU標準品質・中央30%矩形（面積9%）にした測定は、従来5.68秒/5.66秒、新方式1.15秒/1.15秒。準備を含む `exportProject` から完成までの値。各方式のフレーム数は60。Mac配布アプリの編集・写真保存・MP4出力、およびモザイクとガウスぼかしの併用は検証済み。Windows配布アプリの結果はCIで別途記録する。
