# 1.4.0の正式配布と公式サイト更新

Issue: https://github.com/altimix/LumaStudio/issues/32

## 公開する内容

写真保存（#28 / #29）と編集画面の5つの改善（#30 / #31）を1.4.0として配布する。共通の受け入れ条件は各機能仕様に従う。

- 現在の編集結果をPNG / JPEGで指定フォルダへ保存。「プロジェクトの素材にも追加」は初期値オン。写真保存先と素材読み込み先を別々に記憶する。
- 素材追加メニュー、左右パネルの幅変更・折りたたみ、タイムラインの高さの記憶、補助文字の読みやすさ、テキスト追加への入口の整理。
- アプリ、ロックファイル、HTMLマニュアル、OS別起動ガイドと公式サイトのバージョン・配布名を一致させる。更新は案内に従う手動入れ替え。

## 配布の確認

1. mainへの取り込みはスカッシュマージとし、マージする最新内容のWindows / Mac CI、配布アプリ検証、Website CI、CodeQLとCodexレビューを確認する。
2. GitHub Releasesには成功したCIのWindows x64 EXEとMac arm64 ZIPを使用する。公開タグのソースツリーとCIがビルドしたソースツリーを照合する。スカッシュによるコミットIDの違いはツリー比較で確認する。
3. 配布物内のバージョン、README、メディアツールの対応ソース、Macのarm64とad-hoc署名を確認する。Developer ID署名・Apple公証済みとは表記しない。
4. 同じ版の起動ガイド・HTMLマニュアル・ライセンス、固定したメディアツールのソースとビルド手順を添付し、全添付ファイルのSHA256を記録・照合する。既存のリリースとタグは上書きしない。
5. AI検証のモック応答と実API確認を区別する。CIの合格をすべてのPC・GPU・長時間4Kでの確認済みという意味にはしない。

## 公式サイト

配布物が実際に公開された後に、`lumastudio-official` Workerだけを更新する。最新の編集画面は実アプリで撮影した画像を使い、写真保存と5つのレイアウト改善、記憶する設定を説明する。従来の解説動画・音声編集例・映像クレジットを保持し、旧動画の画面には現行版と違う部分があることを示す。

公開後はPC / 390px幅の表示、全ページ・内部リンク・マニュアル検索・404と、新しい版のすべてのダウンロード先を確認する。アプリの配布物をサイトに複製せずGitHub Releasesへ案内する。
