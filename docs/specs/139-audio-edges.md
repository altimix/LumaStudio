# 音声の冒頭・末尾の雑音対策

Issue: https://github.com/altimix/LumaStudio/issues/139

## 対象

MP3をタイムラインで再生すると冒頭・末尾に雑音が入るという報告に対応する。元素材は変更せず、音声の開始位置と、音が切り替わる境界を修正する。

## デコードと実音声の長さ

16/22.05 kHzのMP3では、FFmpegで冒頭に `-ss 0` を指定するとエンコーダー遅延の補正が乱れる場合がある。プレビューとミックス書き出しでは、読み込み開始位置が0秒のときシークを指定しない。途中の8秒窓は従来どおり最大1秒の事前デコードを維持する。

素材の `duration` とクリップの配置・長さは維持する。波形作成時に既に数えている48 kHz PCMのサンプル数から `audioDuration` を求め、音声が実際に存在する終了位置として使う。MP3コンテナーのエンコーダー遅延・パディングを実音声と取り違えない。末尾以降は無音とし、最後のサンプルを繰り返さない。

`audioDuration` は省略可能。旧プロジェクトを開くと通常の素材解析で補われ、クリップや素材の編集上の長さは変化しない。プロキシの再作成に失敗して原本へ戻る場合も、同じ素材リビジョンの保存済み値を維持する。メインプロセスで有限・非負・素材長以下を検証する。キャッシュのフレーム数と各縮尺の波形データ数が一致しない場合は波形を再作成する。

## 音の境界

音声クリップおよび動画内音声の露出した開始・終了には、最大3 ms（短い区間はその半分）の音量ランプを適用する。音声終了がコンテナー長より短い場合も、実際のサンプル終端に適用する。トリミング・速度変更を反映したシーケンス時刻で計算し、通常の音量と長さは保持する。

同じ素材を連続した参照区間で分割し、両側に実音声が続く境界は加工しない。実音声が分割位置で終了して後続クリップが無音になる場合は、終了ランプを適用する。ユーザーが設定したフェードや音声トランジションがある側は、その設定を使う。正逆プレビュー、MP4/MP3のミックス書き出しは共通の境界計算を使う。未編集MP4をそのままコピーする書き出し経路は、元ストリームを保持する。

## 検証

- 16/22.05/44.1/48 kHz、CBR/VBRのMP3で、冒頭と8秒窓を含む末尾を連続デコードのPCMと照合する。
- WAV、AAC動画内音声、無音、トリミング、速度変更、連続分割、トランジションを確認する。
- MP3書き出しと文字起こし用音声の生成でも、低レートMP3の冒頭を連続デコードしたPCM入力と照合する。
- 実アプリの音声出力をPCM録音し、冒頭の波形、境界の不連続、実音声終了後の無音を検証する。
- 旧プロジェクトの再読み込みと元ファイルの保護、Windows/macOSパッケージ検証を行う。

提供された48 kHzステレオMP3は、全区間のデコード窓と連続PCMが一致した。既存実装の実アプリ再生音も元PCMと一致し、macOS標準デコーダーでも冒頭の短い突起が確認された。修正版のmacOS配布アプリでは、全曲を録音して3 msランプを含む期待PCMと照合し、音声エラーがなく、終了後は無音になることを確認した。

元素材に既に含まれる突起への補正には、既存の音量キーフレーム・フェードを使う。自動的に全素材の先頭・末尾を長く消音すると正常な音まで失うため、素材に合わせた設定とする。提供素材・録音・補正コピーはローカルの検証用ディレクトリーで扱い、Gitや公開CIの成果物には含めない。短い補正サンプルでも雑音が残るとの返答があり、報告された音の発生位置を追加調査している。ユーザーの症状全体の解決とは扱わない。
