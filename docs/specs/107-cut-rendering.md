# カット境界と図形合成の安定化

Issue #12。Cのレーザーツールで分割した前後、矢印・四角・丸を重ねた際のブラックアウトと音声のつなぎ目を修正する。

- 通常のカットも、再生方向にある各表示トラックの直近の映像を最大2秒先から準備する。逆再生はクリップの最終フレームを準備する。
- 図形の追加・移動など、映像の素材参照時刻を変えない編集でデコード済み映像を無効にしない。ユーザーのシーク、素材・開始位置・in点・速度の変更では引き続き再同期する。
- MP4合成の開始・終了を出力FPSのフレーム番号へ丸め、FFmpegのマイクロ秒丸めによる境界の欠落を防ぐ。素材末尾の不足は最後のフレームを保持するが、クリップの終了以降や明示的な隙間には表示しない。
- 出力全体の長さも同じフレーム境界へ丸める。非常に短いシーケンスでも最低1フレームを出力し、編集FPSと出力FPSの違いで末尾に黒いフレームを追加しない。音声だけのクリップは1入力だけを開く。
- 図形の透明部分から元映像が見える。図形の描画は従来どおりプレビューと書き出しで共有する。
- 音声は48 kHzのサンプル単位で長さと配置を決める。等速では不要な速度変換を通さない。AAC等は最大1秒前からデコードし、その準備区間を取り除いてカット位置に配置する。
- 不連続な隣接音声の境界に最大3 msのフェードを適用する。同じ素材の連続区間を単に分割した場合や、明示的な音声トランジションのある境界には追加しない。プレビューと書き出しで共通の音量曲線を使う。
- プロジェクト形式は変更しない。元素材、保存済みの編集点、Undo/Redo、トラックロックを保持する。

## 検証

- `tests/export.test.cjs`: 異なる素材・出力FPSのカットを全フレームの画素で検査し、既存の隙間・透明度・トランジション検証も維持する。
- `tests/cut-audio.test.cjs`: 30 FPSのミリ秒に一致しない分割をPCM全サンプルで比較し、AACのデコード開始ノイズを元のデコード結果と比較する。
- `src/transitions.test.ts`: 連続音声にはフェードを追加せず、不連続な境界だけを短いフェードで処理する。
- `scripts/verify-cut-rendering.cjs`: 実アプリでCによる分割、Undo/Redo、保存再読込、3種類の図形、再生画素とMP4全フレームを検証する。テスト専用のプロファイルを使う。
