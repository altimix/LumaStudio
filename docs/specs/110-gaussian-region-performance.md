# ガウスぼかしの範囲合成高速化（Issue #110）

## 目的

矩形の一部だけをガウスぼかしにする場合、全画面の各画素で「範囲内ならぼかし」を判定する処理を減らす。ぼかしの計算対象は全画面のままにして、境界の外側から参照する画素と `sigma` の意味を維持する。

## 適用条件と処理

H.264の不透明映像で、実際にデコードされた画素の縦横比と加工後の枠が一致し、選択矩形が上下左右の端から十分離れている場合に適用する。非正方画素、クロマキーや透明素材、極小・端を含む矩形、レターボックスが必要な素材では従来処理を使う。これらは見た目だけでなくアルファ成分や色形式も変わり得るためである。

FFmpegの `gblur` は引き続き全画面へ実行する。元画像とぼかし後の画像から、選択矩形を含む偶数座標の小さな領域を切り出す。その領域内だけでY・U・V・アルファの各面に元の選択式を適用し、周囲の未加工部分と連結する。YUV420の色差面は座標が半分なので、式の境界を各面ごとに計算する。処理後は従来の合成・色変換・エンコードへ渡す。

## 受け入れと測定

`node scripts/benchmark-export-gaussian.cjs test-results/export-gaussian` は同梱デモの2秒、960×540、24 FPS、CPU標準品質、中央30%四方を測る。手元では従来方式1.213秒、新方式0.416秒だった。双方の48フレームを含むMP4のSHA-256は一致した。素材や端末が違えば速度は変わる。

自動テストでは、変化するH.264映像と複数の選択矩形・強さで、完成MP4の全フレームを復号したRGBAが従来方式と一致することを確認する。透明/クロマキー、縦横比違い、画面端、極小画像は従来方式となる。既存のガウスぼかし・モザイク併用のパッケージ版検証も通す。元の素材は変更せず、完成した一時MP4だけを出力先へ置き換える。
