# Windows動画編集の基礎仕様

状態: 初期実装の受け入れ仕様 / Issue #1

## 利用者の目的

ローカルの素材を読み込み、複数トラックに配置してカット・色・テロップ・音量を調整し、編集を保存して、H.264 / AACのMP4に書き出す。

## 編集モデル

- 最大24トラック、最大2,000クリップ。上の映像トラックが前面。同一トラックでは開始時刻が後のクリップが前面。
- クリップの `start` と `duration` はシーケンスの秒、`in` は素材の秒。参照する素材時刻は `in + (time - start) * speed`。終了時刻は区間に含まない。
- 移動・トリミング・分割はシーケンスのフレーム境界へ揃え、最小長は1フレーム。素材の参照範囲を超える操作は禁止。
- ロックしたトラックのクリップは変更しない。表示・ミュート・ソロはプレビューと出力へ反映する。
- クリップがあるトラックをロック中はシーケンスFPSの変更を拒否し、解除方法を表示する。名前やフレームサイズだけの変更ではクリップの時刻を丸め直さない。
- Ctrl+Bは選択したクリップだけを分割する。未選択時には編集も履歴追加も行わない。
- リップル削除は削除対象トラック内だけを詰め、重複区間を二重に差し引かない。
- 編集履歴は80段階。選択、再生位置、プレビュー画質は編集履歴に含めない。

## 素材と保存

- 動画・音声・静止画をファイルダイアログまたはドロップで読み込む。未対応素材はエラーを表示する。
- 素材ファイルは変更しない。プレビュー用変換と波形はアプリデータ内のキャッシュに作成する。
- `.luma` version 1 はJSON。素材の絶対パス、メタデータ、トラック、クリップ、マーカー、シーケンス設定を保持する。素材自体と一時的なURLは埋め込まない。
- Windows版の素材参照はファイルシステムの絶対パスに限定し、HTTP URLなどをFFmpegへ渡さない。
- 素材の波形配列、音声有無、コーデック、寸法、FPS、サイズを読み込み前に検査する。欠損した素材があっても、不正なメタデータをRendererへ渡さない。
- 保存は一時ファイルの書き込み後に置換する。編集中断後1.5秒で別の自動保存を作成し、次回起動で復元を提示する。
- 保存ダイアログの拡張子フィルターだけに依存せず、メイン処理で保存先の拡張子と元素材との一致を検査する。ジャンクションなどの別名も解決し、素材の上書きを拒否する。
- 移動した素材はオフラインとして表示し、同じ種類・十分な長さの素材に再リンクできる。

## プレビューと出力

- Canvas / Web AudioのプレビューとFFmpegの出力で、配置・速度・レイヤー順・色・テロップ・フェード・音量の設定を共有する。
- H.264 / AAC、720p・1080p・4K・縦型・正方形のMP4出力設定を持つ。CPUでエンコードする。
- 既存の出力は新しい出力の完成後に置換する。中止・失敗時は部分出力を取り除き、元の出力を維持する。素材と同じパスへ出力しない。
- 日本語と改行を含むテロップを画像化して合成する。
- 厳密な色管理とピクセル完全一致は保証しない。テスト用単色素材では、レイヤー・空白・文字の色領域と音声有無を数値で検証する。

## 今後の検証と対象外

長時間4K、多数の素材、VFR、別Windows端末、GPUごとの性能は追加の互換・耐久試験が必要。Premiereプロジェクト、マルチカム、キーフレーム、HDR、トラッキング、自動文字起こしは初期仕様に含めない。

## 追加の回帰条件

- 素材が別種類・短いファイルに置換されていたら、保存済み編集を保ったオフライン素材として開き、再リンクできる。
- 2,000クリップ・2,000素材を超える操作は全体を拒否し、履歴や選択を変更しない。
- 名前やテキスト欄のフォーカスだけで編集履歴を増やさない。実際の入力は1回のUndoで戻せる。ロック中の名前は編集できない。

- オフライン素材を使用する出力は再リンクを求めて拒否する。再リンクで素材の長さを短縮せず、保存済み参照区間の有効性を保つ。
- 小数の素材IN点は、数値欄をフォーカス・blurするだけでは丸めない。プロジェクトの切替時は以前のクリップのコピーを破棄する。

- 手動保存で未保存編集がなくなったとき、開く・新規作成が成功したとき、復元候補を明示的に破棄したときは古い自動保存を除去する。書き込み待ちの古いデータで復活させない。復元した編集中のデータは自動保存を継続する。
- 新規プロジェクトへの切替は非同期の復元データ削除より先に保存先を解除する。削除が失敗しても以前のプロジェクトへ保存しない。
